# 家簿 · 产品需求

> 当前版本：v0.20（2026-10-27）。本文只描述产品需求与已确认的产品规则；技术实现见 [工程文档](../README.md#工程)。

## 1. 一句话

首版做成一个**以聊天为首页、可离线暂存的 Android App**：从设置到日常使用都通过与 AI 对话完成；信息明确就直接记账，缺项或识别不确定才追问；记录可改可撤。

## 2. 核心方向

- **对话完成日常记录**：首页是与 AI 的对话窗口，也是最高频的界面。文字和图片都能直接发进来，由 AI 辅助录入；不以手工填表为默认流程，但保留手工编辑和手动“记一笔”（AI 暂时不可用时也能记账，见第 4 节）。也可以用自然语言快捷问数、查资料。
- **关注账户积累，不做预算管理**：用途账户可自由增减，按月拨入、支出扣减、剩余持续结转。
- **家庭资料能存也能查**：原图留存，AI 提取关键信息供查询和比较；内容以带类型的 JSON 组织，没有专用模板也能默认渲染，有专用模板则更准确。
- **3 个主界面**：聊天首页、总览（Dashboard）、历史 / 搜索，控制首版复杂度。
- **一切按空间隔离**：空间是独立账本，自带资金账户、用途账户、记录、资料和聊天。每个账号自动拥有一个仅自己可见的默认个人空间；“家庭”是邀请了其他成员的普通空间。不是成员的空间对你完全不存在。详见第 3 节。
- **按空间聊天与记录，对话一对一**：每个空间有自己的 AI 上下文。AI 对话永远只有“你和 AI”两方，不会有第三方加入：在共同空间里，每位成员各自和 AI 对话，其他成员看不到、也不能回答你的对话；对话中记下的账目和资料照常写入当前空间，对全部成员共享。
- **离线使用**：没有网络时可以查看已同步到手机的记录；新输入的文字和照片先存在本机，显示为待处理，联网后再交给 AI 整理入账。
- **暂不接入外部接口自动拉取数据**（如银行账单），未来再考虑。
- **管理员管得了服务，管理功能里看不到内容**：服务的管理员负责账号、AI 模型和用量；管理功能里没有任何查看账本和聊天内容的入口，这由服务端的结构保证。能直接操作服务器的人在技术上能读到数据，这一点软件防不住。详见第 8 节。
- **可以让自己的脚本和 agent 以“你”的身份使用家簿**：在 App 设置里创建个人 API key，权限不超过你本人；key 能直接调用 AI 在对话里用的那些查询和记账功能，但不能和 AI 对话。详见第 8 节。

### 已确认的交互原则

- **信息明确就直接记好**：金额、真实付款账户和逻辑用途等必要信息齐全、能明确匹配时，AI 直接入账并回复简洁的记录卡，支持随时修改或撤销，**不要求每笔再点确认**。缺少关键信息，或图片中的金额、内容识别不确定时，先追问再记录。
- **首次设置也通过对话完成**：首次使用时，通过对话创建真实资金账户和逻辑用途账户，设置各自的起始余额，以及用途账户的每月拨入计划。从启用时开始记新账，无需补录此前明细。用户可以分次提供信息，AI 针对缺项追问；设置完成后展示账户摘要，之后仍可通过对话修改；也可以不经过 AI，在设置里手动建账户、设起始余额和每月拨入计划（见第 6 节）。**起始余额只用于衔接已有资金，不算启用后的新增收入或消费。**

## 3. 空间：记录的隔离单位

**空间**是核心概念：一个完全隔离的账本，包含它自己的真实资金账户、逻辑用途账户、记录、家庭资料，以及每位成员各自与 AI 的对话。任何用户都可以创建多个空间；“家庭”只是邀请了其他账号作为成员的普通空间，没有特殊类型。

| 规则 | 说明 |
|---|---|
| **默认个人空间** | 每个账号创建时自动获得一个仅自己可见的默认个人空间。人人都有，不是需要特意去做的动作。默认个人空间不能邀请其他成员；需要共享就另建空间。 |
| **完全隔离** | 不是成员的空间对你不存在：看不到名称、数量或任何动态信号；其他空间的笔数、合计或提示不会出现在任何你能看到的地方。服务端对非成员一律按“不存在”处理。 |
| **账户属于空间** | 真实资金账户和逻辑用途账户都属于某个空间，记录只能关联本空间的账户。同一张真实银行卡可以在两个空间里分别建账户；每个空间只显示本空间的流水和本空间口径的余额，不显示整张卡的余额。因此整张卡的余额不会在 App 内对平，这是有意的取舍。 |
| **AI 只在当前空间工作** | AI 只把记录写入当前空间，不推断也不建议其他空间，看不到其他空间的内容；每个空间的聊天历史和 AI 上下文互相隔离。 |
| **对话一对一** | 聊天只在你和 AI 之间进行：没有群聊，其他成员不会加入、看不到、也不能回答你的对话或其中的追问。同一空间里每位成员的对话互相独立；共享的是对话产生的记录，不是对话本身。AI 回答你时也只参考你自己在这个空间里的对话，不读别人的对话。 |

### 账号与空间成员

**用户账号**（登录身份）与**空间成员**是两个实体。加入空间时生成一条空间成员记录（空间内显示名、角色“所有者 / 成员”、状态“在空间中 / 已退出”、加入与退出时间），同一账号在同一空间只有一条。退出后重新加入时，沿用原来那条成员记录和空间内显示名，本人可以修改。记录、资料和变更事件都指向“由哪位空间成员创建”。

- 成员**退出或被移除**后：其记录保留，仍显示创建者名字并标“已退出”；本人失去对该空间的全部访问。
- **重新加入**时复用同一条成员记录，旧记录自动重新关联到本人。

### 成员管理

创建空间、改名、所有者邀请已有账号（只有所有者能邀请，普通成员看不到邀请入口；首版只有预建账号，没有公开注册）、所有者移除成员、成员自行退出空间、转让所有者身份、删除空间。

- **邀请要对方接受**：邀请发出后，对方在 App 里看到“谁邀请你加入哪个空间”，接受后才成为成员；接受之前看不到这个空间的任何内容。对方可以拒绝；对方接受前，所有者可以撤回任何一条待接受的邀请；被拒绝或撤回后可以再次邀请。所有者转让给别人后，之前发出、还没被接受的邀请继续有效，新所有者可以撤回（P71，2026-10-29 取代 P64 中“邀请人离开则邀请作废”）。以前退出过的人重新加入同样要接受邀请。
- **默认个人空间**不能邀请他人、不能退出、也不能删除。
- **转让所有者**：所有者可以把所有者身份转给空间里任何一位现有成员。
- **最后一位所有者**不能直接退出：空间里还有别人时，先把所有者身份转给其中一位；只剩自己时，可以删除空间。
- **删除空间**：只有空间里只剩你一个人时才能删除；确认时要输入空间名；删除后不能恢复。
- **退出或被移出时，手机上这个空间的内容一律清除**，包括还没上传的文字和照片：
  - **自己退出**：确认之前，如果还有没上传的内容，提示“有 N 条还没上传，退出后会丢弃”，确认后清除；
  - **被别人移出**：手机发现后马上清除，再提示你已不在这个空间、本机上的内容（含没上传的）已清除。

### 照片占用的空间

照片（账和资料上的原图、聊天里发的图）是服务器上最占地方的东西，将来如果收费，存储是要算钱的资源，所以首版就按空间统计（P68）：

- **按空间算**：一个空间的“照片占用”= 这个空间里用到的所有照片的大小，包括账、资料、聊天里的照片，原图和两张缩略图都算；已撤销的账上的照片还占着地方，也算。同一空间里同一张图只算一次；两个空间各用了同一张图，两边各算一次——不会因为“别的空间也有这张图”就少算，否则从数字的变化就能猜到别人的空间里有什么。只算照片文件，不算账、资料这些文字记录。
- **在哪看**：空间设置里显示本空间的照片张数和占用大小，空间成员都能看到；只给总数，不按模块或成员拆开。管理员能看到所有空间的占用、每天的记录和服务器实际用了多少（同一张图在服务器上只存一份，按实际算），看不到照片本身。
- **首版只统计、不收费、不设上限**；每天记一次每个空间的占用，留作将来按“GB·月”计费的依据。
- **从账上去掉的照片不保留**（P67）：编辑一笔账或一份资料时把某张照片去掉，这张照片一天后从服务器上清掉，变更记录里只写“移除了一张照片”，不能再点开。**撤销**一笔账（或作废一份资料）不一样：它还能恢复，所以照片照常保留。同一张照片如果还挂在本空间别的账或资料上，或者还在你自己的聊天里，就不会被清掉。

### 入口与外观

App 打开即进入上次使用的空间；当前空间显示在页面右上角的空间徽章中，点开空间列表 / 选择器切换，**不做整屏换色**。每个空间创建时从固定色板选一个点缀色，只用于空间徽章和小标记。

### 应用锁（可选，默认关闭）

可在设置中开启 App 级锁：生物识别（指纹 / 面容）或手势图案密码，均以数字 PIN 兜底。启动 App 时验证；从后台返回且超过设定时长时再次验证。开启后，通知不显示具体内容，多任务切换界面里的缩略图被遮挡。首版锁整个 App，不按空间分别加锁。

### 扩展预留：空间内的模块与按模块授权

将来空间可能不只记账，还会存放照片、故事、影像等家庭记忆；孩子也可能加入空间浏览记忆，但不应看到家庭财务或家人的健康资料。首版不做这些能力，但结构上提前留好：

- **空间内容按模块划分**：账本（记录、账户）、资料（如检查单）是首版的两个模块；“记忆”等模块以后加入，不改整体结构。每条内容都标明所属模块。
- **成员按模块授权**：每位成员对每个模块有一个级别：不可见 / 只读 / 可编辑 / 可管理。首版不做授权界面，所有成员默认全部开放；但从第一天起，所有访问都经过同一个权限判断（“这位成员能否对这个模块做这件事”），不存在“是成员就全部放行”的捷径。
- **无权模块视为不存在**：与空间规则一致，不显示入口、数量或“无权限”提示。**唯一的例外在聊天里**：聊天中按 ID 实时读取的卡片（如记录卡、资料卡）读不到时，卡片显示“此内容你已无权查看”；历史回复里保存下来的文字和图表按原样显示，不追溯处理。
- **AI 与同步遵守同一套权限**：AI 组装上下文时拿不到无权模块的数据；手机只同步有权限的模块，权限被收回时本机对应数据随之清除。
- **单条内容可见范围**：例如某位家人的体检报告只给本人和指定成员看。首版只在数据上预留字段，不实现。
- **不区分成人 / 未成年账号**：能参与空间协作的孩子用普通账号即可，差异完全由按模块授权表达。

## 4. 首版界面：三块内容 +「我的」

底部导航是**聊天、总览、历史、我的**四项：前三项是内容界面，「我的」进入账号与设置。空间是所有记录的归属，不另造一套平行界面；三个内容页右上角显示当前空间徽章（空间点缀色底），点开空间列表切换。

| 界面 | 内容 |
|---|---|
| **聊天首页**（默认入口） | 顶部显示当前空间徽章，点开可切换；中间是你和 AI 的一对一对话：AI 的回复是文字与记录卡、指标、表格、选项等组件混排，文字边生成边显示，回复顶部能看到 AI 正在做哪几件事（见下文“聊天回复”）；底部是带铅笔和回形针的纸卡文字框，最右端一个圆形按钮——有内容时是发送，AI 处理时（文字框为空）变成停止。回形针打开附件弹层，在相册页拍照 / 选图，或在文件页选择图片文件。首次设置也在这里完成。 |
| **总览** | 先看真实资金账户与逻辑用途账户余额，再看近期变化、待处理的离线项目和家庭资料摘要。不以预算使用率或“剩余额度”为中心。 |
| **历史 / 搜索** | 统一检索账目与家庭资料，在当前空间内按成员、账户、标签、类型和时间筛选；进入详情后查看原图、变更记录，执行编辑或撤销。 |
| **我的** | 账号（改密码）、应用锁、个人 API key、关于与开源许可。空间与成员管理仍从空间徽章弹层进入。 |

「我的」是设置的固定入口；三个内容页的右上角留给空间徽章，不再放“我”按钮。

### 记录卡是关键交互单位

一张卡只显示用户核对所需的信息：记录类型、金额或资料标题、真实账户、逻辑用途、创建成员（已退出成员标“已退出”）、状态与时间。卡上直接提供“编辑”和“撤销”；撤销后保留变化记录。

记录状态：离线输入标为“待上传” → 上传后标为“待 AI 处理” → 完成后显示“已记录”。失败时保留本地内容并允许重试。

**修改冲突不自动覆盖**：同一条记录在两处被修改（例如一台手机离线时改过），后同步的一方在记录上看到“有冲突”提示，点开能看到两个版本、选择保留哪个；新增的记录不会冲突。

- **撤销优先**：如果另一边把这笔撤销了，你这边只显示“这笔已被撤销”，另给一个明确的“恢复并改成我的版本”按钮；选“保留我的版本”不会悄悄把撤销掉的账恢复。
- 冲突解决之前，余额按服务器上的版本算。

### 聊天回复：文字与组件混排、逐步显示

AI 的回复以文字为主，信息适合结构化展示时，在文字之间插入组件。聊天界面由独立开源库 [ChatWeave](https://github.com/zz-howard/chatweave) 实现，家簿提供手账外观和自己的业务组件。

| 组件 | 什么时候出现（举例） |
|---|---|
| 记录卡 / 资料卡 | 记好一笔账、整理好一份资料（见上文“记录卡”） |
| 指标 | “教育用途还剩多少？”——显示余额，负数时有“超支”标签 |
| 表格 | “这个月餐饮花了哪些？”——列出明细 |
| 简单趋势图 | “孩子的视力这两年怎么变的？”——历次数值的折线（同时提供文字摘要） |
| 选项 | 追问（“用哪张卡付的？”），点一下就回答 |
| 确认 | 不可撤销的操作在执行前请你确认（v1 对话里基本没有，日常记账仍然直接入账、靠撤销保证安全） |
| 小表单 | 首次设置时一次补齐几项信息（账户名称、起始余额、每月拨入） |

规则：

- **看得见 AI 在做什么**：每条 AI 回复的最上方有一条“过程”。AI 查数据、对比的时候，这里逐行显示它正在做的事，例如“查本月餐饮支出 ✓ 0.8 秒”“对比上月 ⏳”；回答写完后自动收起成一行，例如“查了 3 项 · 用时 4 秒”，点一下可以展开再看。
  - 每一行是一句好懂的说明，不显示查询条件和查到的原始数据；有的步骤会多一句结果说明，例如“找到 23 笔”。
  - 某一步没查到，只在那一行标“没有完成”，其他步骤和回答照常；AI 会在回答里说明哪部分没查到。
  - 需要你确认或回答的一步显示“等你确认 / 等你回答”，确认卡、选项在回复正文里；你回答后这一行接着做完，并注明“你已确认 / 你选了……”。
  - 生成中点输入栏右端的圆形停止按钮（发送按钮在 AI 处理时变成它；消息区里没有“停止生成”文字按钮），正在做的那一步标“已停止”。
  - 不显示 AI 的“思考过程”原文。
  - AI 在想、还没有内容可看时（第一个字出现之前，或一次查询做完、下一段文字出现之前），署名旁显示“思考中”；文字逐字出现时、有步骤在运行时不显示（以过程条为准）。
  - 过程和对话一样只有你自己看得到；复制回复、通知和搜索都不包含过程。只说几句话、没有查数据的回复没有这一条。
- **问你一句，就在原地等你**：AI 做事做到一半需要你确认或补一句信息时（例如“用哪张卡付的？”，或改一笔记录之前），这条回复**停在原地**等你：
  - 卡片上是 AI 给的选项（或确认 / 取消、小表单），另外**固定多一个“输入其他内容”**。
  - 卡片等你回答的时候，**底部的输入框暂时锁住**，提示“先回答上面的问题”，免得一句话发出去不知道算回答还是新问题。
  - 想说选项以外的话，点“输入其他内容”：输入框解锁，上方挂一个小标签“回答：用哪张卡付的？”，表示这次打的字是在回答这张卡，不是一条新消息。标签上有 ✕，点了回到选卡片的状态，输入框重新锁住，已经打的字留着。你写的话原样交给 AI 理解（例如在确认卡上写“改成 72 块再记”）。
  - 不管点选项、确认还是打字，回答都记在这张卡片上，**不会**变成对话里单独的一条消息；AI 在**同一条回复**里接着做完（例如接着生成记录卡），过程条也还是同一条。
  - 等多久都可以：退出 App、换另一台手机，回来后仍能回答，回答后照常继续。
  - 不想回答了，点“停止生成”：这次询问作废，这个问题对应的那笔不会记。停止只取消还没做完的部分：同一条回复里已经记好的账保留，各有自己的记录卡，可以单独撤销。卡片显示“已停止”，并写清这条回复记了什么、没记什么，例如“已停止：这条回复里已记 1 笔（见上方记录卡），第 2 笔没有记”。
  - 问题有有效期：**改记录之前的确认 24 小时**（时间长了记录可能已经变了），**补信息的问题 7 天**；过期后卡片显示“已过期”，这条回复结束，需要的话重新说一遍。
  - 你确认之前，这笔记录如果已经在另一台手机上被改过，AI 不会照旧改，会告诉你记录变了、需要的话重新问你。
  - 回答已经写完、最后顺带问你一句（例如“要不要设成每月固定支出？”）不一样：那条回复已经结束，输入框不锁，你的回复就是一条新消息，AI 再回一条新的。
- **服务器出状况也接得上**：AI 回复到一半服务器重启或出错时，它会自动在**同一条回复**里接着说（已经显示的文字保留）；接连两次都没成功，这条回复标“没有完成”，旁边有“重试”，点了把上次没做完的接着做完（新的一条回复）：例如“午饭 50，停车 10”午饭已记好、停车出错，重试只记停车，午饭不会再记一笔（P64）。
- **逐步显示**：文字随生成逐字出现，不用等整段回答写完；组件在它的位置先出现占位，内容齐了一次性显示。不会出现“先显示一段文字、再变成一张卡片”的跳动。
- **数字只来自真实记录**：组件里的金额、余额、笔数由服务端按当前空间实际查询得出，AI 不自己编数字。
- **断网也不乱**：生成过程中断网或切到后台，已显示的内容保留；联网后接着显示剩下的部分。最终以服务端保存的版本为准，你自己的两台手机看到的一致。
- **追问可离线回答**：没网时也能点选项，回答先存在手机上，联网后补发；回答过的追问在你的所有设备上都显示“已回答”，不会被重复回答。
- **点了先显示“提交中”**：点选项或确认后，卡片先显示“提交中”（离线时“已排队”），服务端确认后才显示结果。虽然对话是一对一的，服务端仍可能拒绝（权限变化、相关记录已被改动或删除、信息不合规），你也可能已经在另一台手机上回答过，所以不提前显示“已选择”。
- **永远看得懂**：旧版本 App 遇到不认识的组件时显示一段文字说明，不白屏、不报错。
- **组件只是展示**：点组件上的按钮只是向服务端“提出请求”，执行前服务端仍按空间成员身份和模块权限校验。

### AI 暂时不可用时：手动记一笔

记账这个核心功能不依赖 AI。默认的 AI 接入（ChatGPT 订阅）登录失效或额度用完时：

- **不会自动改用按量付费的接口**（见第 9 节）。AI 聊天暂停，聊天页提示“AI 暂时不可用”，并给出“手动记一笔”按钮；查看记录、编辑、撤销照常。
- **手动“记一笔”**是一张简单的小表单，顶部切换“支出 / 收入 / 转账 / 调拨”，默认支出，字段跟着种类变（支出：金额、付款账户、用途、标签、日期）；退款不在小表单里，在那笔支出的详情页点“退款”记（P65）。它不经过 AI，平时也能用，不只在 AI 不可用时出现。
- 账户也能手动管理：在设置里手动新建账户、设起始余额和每月拨入计划，新用户赶上 AI 不可用也能从头建好账（见第 6 节）。
- **排队等 AI 处理的内容**可以选“改为手动填写”：选了就取消原来的 AI 处理，改用小表单记下，AI 恢复后不会再记一遍。不选就继续排队，AI 恢复后接着处理。

### 权限边界必须显式

空间内容只对该空间的在册成员可见，退出即失去访问。当前空间不仅决定看到什么，也决定新记录写到哪里；**每次读写由服务端按“请求者是否为该空间在册成员”再次校验**，非成员一律当作空间不存在，不能只依赖客户端状态。

### 多语言

- 首版支持**简体中文和英文**两种界面语言，以后可以增加。设置里可选“跟随系统 / 简体中文 / English”，默认跟随系统，选择同步到服务端，换手机不丢。
- 日期、数字按界面语言格式化；币种符号跟着空间的币种走（见第 6 节），不跟语言走。
- AI 用你提问的语言回答，判断不出时用界面语言。
- 你自己起的名字（账户名、标签、资料内容）原样显示，不翻译。
- **预置分类名**（如“餐饮”“交通”）没改过名时按每个人自己的界面语言显示；有人改过名，就以改后的名字为准，所有人看到一样的。
- 英文界面下显示中文内容时按简体中文字形显示；每次发版的更新说明写中英两份。

### 安装与更新

- **服务端地址在 App 里设置**，不写死在代码里；登录、同步、检查更新、下载安装包都走这个地址。自建服务端的人用自己的地址。
- **正式出处是 GitHub Releases**，但**手机只从自己的服务端下载**：服务端定时（每 6 小时，或管理侧手动“立即检查”）从 GitHub 拉新版，核对校验值和签名指纹无误才提供给手机；GitHub 连不上时管理侧可以手动上传安装包（同样校验）。
- **App 内检查更新（v1）**：每次打开 App 查一次，切回前台且距上次超过 24 小时再查，查不到就安静跳过。有新版时首页顶部出现一条不挡操作的提示，点开看更新说明和大小，再点“下载并安装”；不点则 3 天后再提示。下载后核对校验值再交给系统安装器，不在后台偷偷下载，也不静默安装；第一次需要“允许安装应用”授权时先说明原因再跳到设置。
- **两个渠道**：正式版和测试版。
- **版本兼容**：App 和服务端互相检查版本，任一方太老都给出明确提示。只有接口不兼容或严重安全修复时才强制更新；强制更新期间仍能查看手机上的数据，只是不能同步和记新账；还没上传的内容保留在手机上，更新后自动接着上传，不会因为强制更新而丢失。

## 5. 三条关键流程（也是验收场景）

覆盖最常见、最不确定和无网络三种情况。

1. **信息明确的支出：直接记录**
   用户在家庭空间输入“午饭 68，信用卡，日常餐饮”。AI 能明确匹配金额、真实账户与逻辑用途时直接入账，返回记录卡；用户可立即编辑或撤销，不多一步确认。
2. **照片不确定：先追问**
   用户拍下一张视力检查单。App 先保留原图；AI 提取能确认的日期和数值，针对模糊字段或该关联哪位家人提**一个**聚焦问题，这条回复停下来等用户。用户回答后，**同一条回复**接着生成资料卡，仍可回到原图核对。
3. **离线输入：排队后同步**
   无网络时文字与照片写入本地队列并显示“待上传”，用户仍可查看已同步记录。联网后按顺序上传，进入“待 AI 处理”；成功后替换为正式记录卡，失败项保留并可重试，**不能静默丢失**（唯一的例外是退出或被移出空间，见第 3 节“成员管理”：退出前会提示，被移出后也会提示）。

## 6. 账户与记账规则

账户都属于某个空间（见第 3 节）。现实中常见的做法是用专门的银行账户对应不同用途（一一绑定）。家簿改为**在每笔记录上建立逻辑关联**：一个用途可以从不同银行卡支付，一张卡也能承担不同用途。

| 账户类型 | 含义 |
|---|---|
| **真实资金账户** | 银行、理财等账户，表达钱实际在哪里。支持真实支出、收入和账户间转账记录。 |
| **逻辑用途账户** | 为某类事情设立的“心理账户”，核心是持续变化的余额；不要求与某个真实账户或真实可用资金一一对应。 |

规则：

- **一个空间一种币种**：建空间时选，默认人民币；空间里所有账户和记录都用这一种币种，首版不做跨币种。
- **手动建账也可以**：除了在对话里设置，也能在设置里手动新建账户、设起始余额和每月拨入计划，不依赖 AI。
- **用途账户灵活管理**：用户可以新增、改名、调整或移除逻辑账户，并修改每月拨入计划。系统不预设固定账户清单。账户调整时保留历史账目与关联。**“移除”即归档**：归档后不再出现在记账选项和每月拨入计划里，历史账目照常可查；归档前余额须先转到别的账户或备用金，App 引导完成。
- **按月拨入、持续结转**：每月通常拨入固定金额，可调整；自动执行可开关，执行日期可配置，默认每月第一天。未花完的余额累积，不按月清零。拨入的时间规则：
  - 设好以后从**下一个**拨入日开始拨，不补设置之前的月份（避免和起始余额重复）；
  - 拨入日设在 29 到 31 号时，遇到小月就在当月最后一天拨；
  - 时间按空间的时区算，默认取建空间时手机的时区；
  - 服务器停机错过了，恢复后补拨，每个月最多拨一次；
  - 修改拨入计划从下一次拨入开始生效；
  - 每一次拨入都是一条普通记录，可以撤销。
- **月度设置是“拨入计划”，不是预算**：不存在“月额度”，只有持续结转的账户余额。定期拨入、额外调拨与支出都会改变余额。
- **一笔支出同时关联**真实付款账户和逻辑用途账户，分别更新余额，**消费只统计一次**；关联发生在记录上，无需账户一一绑定。
- **超支处理**：允许逻辑账户出现负余额，也支持从兜底 / 备用金逻辑账户调拨补足（**推荐调拨方案**）。
- **自由标签**：支出分类用标签，不限定为固定分类树。每个新空间自带 11 个**预置分类**（P69）：餐饮、买菜、交通、购物、居住、日用、医疗、教育、娱乐、人情、其他；它们和自建标签一样可以改名、删除，也可以再建自己的。
- **后续更正**：修改、删除或退款时，按正常逻辑增减相关账户余额，并留下操作 / 变化记录。
- **退款**是一种单独的记录，挂在原来那笔支出上；可以部分退款，但累计不超过原金额。默认把钱退回原付款账户和原用途。原用途账户已经归档时，问一句退到哪个用途，默认备用金。已有退款的支出不能直接撤销：在对话里 AI 会问“要连退款一起撤销吗”，确认后两笔都撤销；在记录页手动操作时先撤销退款、再撤销支出（P64）。
- **已归档账户上的旧账**：修改或撤销已归档账户上的旧账，照常改那个账户；它的余额因此不为 0 时，App 提示把余额转走。
- **真实资金变化与逻辑调拨分别记清**：真实收入、真实账户间转账是各自的记录类型；每月拨入逻辑账户不等于真实收入或银行转账，逻辑账户间调拨也不产生消费。

展示重点是“现在有多少余额、钱怎样进出和累积”。没花完的钱留在原账户继续累积，这正是用户希望看到的积累结果。

### 示例：用一笔消费检验关联（虚构数据）

教育用途余额 200，要从某张银行卡支付 500。

| 方式 | 结果 |
|---|---|
| 保留负数 | 教育余额变为 −300；下月再拨入 2,000，余额变为 1,700。 |
| **备用金调拨（推荐）** | 备用金先调拨 300 给教育用途，再记录完整支出 500。教育余额为 0，备用金余额减少 300。 |

两种方式中，银行卡都只支付 500，总消费都只有 500；逻辑调拨不需要真实银行转账，也不重复计支出。

## 7. 家庭资料

第一个场景是**家庭成员的视力检查**：留存当次文字和图片资料，方便以后查询、回看。其他资料类型后续逐步加入。

AI 整理方式（已确认）：

- 保留原图（照片本身的完整画质；定位信息和“实况照片”的小视频等附加内容不存，P70），同时提取能明确识别的检查日期与关键数值，关联到相应的家人。
- 支持查询上次检查时间、列出历次结果对比，并回到原图核对；不确定的内容标明或向用户确认。

内容组织：

- **内容带类型，默认渲染**：具体内容以 JSON 组织，每项保留名称、值和类型。基础类型共七种：**文字、数字（可带单位）、日期、图片、单选、多选、表格**。没有专用模板时按内容类型用默认模板渲染，仍能完整记录、清晰展示。
- **和聊天组件同一套做法、各自的格式**：资料和聊天里的内容块（ChatWeave）遵循同样的原则（带类型和版本、显示不了时有兜底文字），共用最小的值类型和 App 里的显示组件，所以资料页和聊天里的同一个数值长得一样；但资料要长期保存、反复编辑，不和聊天内容块共用同一套数据格式。聊天里提到某份资料时只**按 ID 引用**，显示时取最新版本、按查看者当前的权限读取；需要汇总对比时（如历次视力），由服务端转换成趋势图发到聊天里，资料本身不动。
- **专用模板按需增强**：可以为某类资料建立专用数据类型 / 模板，明确字段含义并使用更合适的布局（例如视力检查模板区分左右眼与检查项目），帮助 AI 更准确地整理。新资料**不要求**先有专用模板。
- **官方预置模板**：v1 预置体检、视力、疫苗、证件四种，以后逐步丰富。
- **自建服务端可以加自定义模板**：模板按公开的模板协议编写（纯声明，不含代码），放进服务端指定目录即生效，连到这台服务端的所有 App 都能用；官方模板用同一协议。用 App 登录的普通用户不能自建模板。
- **通用信息只描述记录本身及其归属**；“检查日期”等业务字段属于具体内容或专用模板，不作为所有资料的必填公共字段。

资料的归属与查看：

- **每份资料一定记录**：属于哪个空间、谁创建、谁最后修改、完整修改记录。
- **可关联 0 个到多个对象**（资料说的是谁 / 什么）。首版对象种类：**家人、宠物、房屋、车辆、其他**，以后可以加。家人不等于空间账号：孩子、老人没有账号也可以是家人；正好是空间成员时可以绑定，但不要求。对象由空间成员在 App 里维护，AI 整理资料时会建议关联谁，用户可以改。例如视力检查关联 1 位家人；房产证关联 1 套房屋，再关联几位家人作为产权人；Wi-Fi 密码这类不关联任何对象。
- **对象的维护规则**：
  - 已经关联了资料的对象只能归档，不能删除；没有关联任何资料的对象可以删除。
  - 改资料关联的对象（例如关联错了家人）会留下修改记录。
  - 不做“合并对象”。新建对象时（不论是自己建还是 AI 建议），先看本空间里有没有同一种类、同名的对象，**已归档的也算**：和已归档的同名，就自动取消归档、直接沿用，用户不需要察觉；和现有的同名，就直接用现有的那个。
- **模板声明规则**：这类资料要不要关联对象、关联哪种、几个，以及哪个字段是“事件日期”（体检的检查日期、证件的签发日期），用来排时间线。没有模板的资料默认用录入日期，可以改。
- **筛选**：关联对象（含“未关联”）、资料类型、日期范围（按事件日期）、创建人。
- **查看**：每个对象一页，按时间线列出相关资料；一条全家时间线；同一类型的数值可以前后对比。

家庭资料和账目一样属于某个空间，只对该空间成员可见（见第 3 节）。

## 8. 身份与权限

- 服务端为每位用户建立一个**不可变的内部用户 ID**，它是登录与权限的真实身份；创建账号时同时创建该账号的默认个人空间。在空间内，数据归属记在该空间的成员记录上（见第 3 节）。
- 首版**预建两个“用户名 + 密码”账号**：不需要邮件、短信服务或公开注册。密码只保存安全哈希；登录后由 App 在 Android 安全存储中保管会话。
- 忘记密码先由管理员人工重置：重置后得到一个一次性的临时密码，用户用它登录后必须马上改成自己的密码；重置会让该账号在所有手机上退出登录，原来的密码随即失效。**密码被重置后，本人下次登录时 App 明确提示“你的密码在某月某日某时被管理员重置”**，所以管理员借重置密码冒用账号一定会被本人发现。邮箱登录、手机号登录和自助找回留待以后。
- **账号可以被停用**：管理员停用账号后，该账号立即在所有手机上退出、它的 API key 暂停使用；重新启用后可以再登录，API key 恢复（已过期或已撤销的除外）。停用不删除任何数据，该账号在各空间里创建的记录照常保留。

### 管理员：管得了服务，看不到内容

家簿服务的**管理员**（自己部署时就是部署服务的人）负责账号、AI 模型和用量。**管理功能里没有任何查看账本和聊天内容的入口**：这一点由服务端的结构保证（管理接口里根本没有返回这些内容的功能），不靠管理员自觉。

承诺的边界要说清楚：**能直接操作服务器的人（例如能登录服务器、读数据库和原图文件的人），在技术上能读到数据，这一点靠软件防不住**；真正防住部署者需要端到端加密，首版不做。管理员能重置密码，但重置一定会被本人察觉（见上）。

| 管理员能做 | 管理员看不到、也做不了 |
|---|---|
| 新建账号、停用 / 启用、重置密码；查看某个账号加入了哪些空间（空间名称、角色、状态、加入时间） | 任何记录、账户、余额、标签、家庭资料和原图 |
| 配置 AI 提供方和模型、每类任务默认用哪个模型、各模型的官方价格（带来源和核对日期） | 任何聊天内容：你说的话、AI 的回答、追问和你的回答、“过程”条上的具体说明 |
| 查看用量与成本：按空间、成员、提供方、模型、日 / 月统计，以及提示词缓存省下的金额；点开一次 AI 回复，只看到它调用了几次模型、每次用了多少 token、按官方价格折算多少钱、用了多久，以及每一步是哪一类操作（例如“查询统计”），看不到具体查了什么 | AI 每一步的具体说明、查询条件和结果；运行日志里的任何内容 |
| 查看空间列表：空间名称、类型（个人 / 共享）、创建者、成员数、创建时间——有名称才能把用量、账号和空间对上号 | 空间里的任何内容（名称以外的一切：账本、资料、聊天） |
| 查看每个空间的照片占用（张数、大小、每天的记录）和服务器实际占用（P68） | 照片本身，以及占用是由哪些照片、哪些记录构成 |
| 查看、撤销某个账号的 API key（例如怀疑泄露）；让某个账号在所有设备上退出登录 | 通过管理功能以用户的身份登录或操作（重置密码会被本人察觉，见上）；创建用户的 API key |

- **管理员身份和家庭成员账号是分开的**：用 App 的账号登录不能做任何管理操作，管理员也没有进入任何空间的身份。
- **管理的入口**：自己部署的人用服务器上的管理命令完成上表所有事情；服务端还提供一套带版本号的**管理 API**，可以基于它做图形化的管理控制台。官方的管理控制台是一个**单独的服务，不在本仓库**，本仓库也不依赖它。
- 管理员的每一次操作都留下审计记录（谁、什么时候、对什么做了什么），审计记录里不含密码和密钥。
- 用户在 App 里**看不到** AI 的用量和成本（首版）。

### 个人 API key

让自己的脚本或 AI agent 以“你”的身份使用家簿：例如让 agent 每天查一下这个月餐饮花了多少，或者把一笔账记进家簿。

- **在 App 的“设置 → API key”里创建**，填写：
  - **名称**：例如“我的记账脚本”，用来辨认；
  - **有效期**：7 天 / 30 天 / **90 天（默认）** / 1 年 / 永不过期。选“永不过期”时明确提示风险：一旦泄露会一直有效，建议设置到期时间；
  - **权限**：只读，或可读写。
- **完整的 key 只显示这一次**：创建后提示立刻复制保存；之后列表里只显示开头几位，用来辨认是哪一个。服务端只保存它的不可逆摘要，丢了只能撤销后重建。key 有固定的开头，泄露到代码仓库时容易被密钥扫描工具发现。
- **列表**：每个 key 显示名称、权限、到期时间、**最近一次使用时间**。随时可以撤销，撤销立即生效。可以改名称；权限不能改，要改就新建一个再撤销旧的。
- **key 就是你，但不会比你大**：key 属于你的账号，不单独选空间：你当前在册的每个空间它都能用，包括以后新加入的空间；能做的事不超过你本人在这些空间里的权限。你退出某个空间，key 对它立即失效；重新加入后自动又能用。账号被停用时 key 一并暂停。不是成员的空间对 key 来说同样不存在。
- **key 不能和 AI 对话**：通过 key 不能发消息给 AI、不能回答 AI 的追问或确认卡片，也不能提交需要 AI 整理的原话或照片——任何会让 AI 运行的请求都会被拒绝。用 key 的一方本身就是脚本或 agent，它需要的是可靠的数据接口，而不是再套一层对话。
- **AI 能用的功能，key 也能直接用**：AI 在对话里能调用的每一项功能（查统计、查余额、搜索记录、搜索资料、记一笔、改一笔……）都同样开放给 key 直接调用，规则和 AI 用的完全一样——同样的参数、同样的权限检查、同样只能在当前空间里、同样的业务校验。只在对话里才有意义的功能（例如“向用户提问”）不开放。
- **另外还能做**：手机上的日常数据操作——查看和同步记录、记账、修改和撤销、上传和查看原图。
- **不能做**：任何 AI 对话功能（见上）；创建或撤销 API key、改密码、让设备退出登录、新建空间、空间成员管理（邀请、移除、退出、删除空间、转让所有者），这些只能本人在 App 里操作；key 也不能使用任何管理功能。
- **只读 key**：只能用查询类的功能和查看类的操作，不能记账或改账。
- **可读写 key 的写入直接生效**：AI 在对话里做需要确认的修改（例如改一笔已有的账）时，会先弹出确认卡等你点确认；key 调用写入功能时**不弹确认卡、直接执行**——调用它的是你自己授权、并为之负责的脚本或 agent。写入照常可以在 App 里撤销，并且每次写入都必须带防重复提交的标识，网络重试不会记成两笔。
- **做过什么都有记录**：通过 key 做的每件事都照常记在你名下，并注明“**通过 API key：名称**”——记录卡、记录详情的变更记录和历史里都看得到，同一空间的其他成员也看得到这个标注。key 不会让 AI 运行，所以不产生 AI 用量。
- **防滥用**：每个 key 有调用频率上限，写入类的上限更低；超过时返回“请稍后再试”。每个账号最多同时有 20 个有效的 key。
- 以后（不在首版）：基于服务端公开的接口说明（OpenAPI），提供开源的命令行工具和 agent 平台组件，让 agent 直接用 API key 记账和问数。

## 9. AI 接入原则

- 采用**独立的家庭助手**；对话是一对一的（一位用户和 AI），每位成员在每个空间里有自己的会话；AI 上下文按空间隔离，并且只用发起者本人在该空间的对话历史，不读其他成员的对话。
- 服务端有自有的模型接口，支持更换模型或服务商，按配置切换与降级。
- **默认使用一份系统统一配置的 ChatGPT 订阅授权**（官方 “Sign in with ChatGPT”），供两位用户共享；不要求每位用户分别登录或绑定模型账号。App 自己的用户名密码只负责身份和权限。
- **不把按 token 计费的付费 API key 作为默认接入，也不在额度耗尽或订阅接入失败时自动切换到按量付费**；付费备选只有在显式开启时才会被使用（管理侧的“启用付费备选”开关，默认关闭）。
- **订阅不可用时**：AI 聊天暂停，App 提示“AI 暂时不可用”；手动记账、查看、编辑、撤销照常（见第 4 节“AI 暂时不可用时”）。
- 服务端必须**先按当前空间（且请求者是该空间成员）组装上下文，再调用共享模型**，避免共享凭据导致不同空间的内容混在一起。AI 只写入当前空间，不推断、不建议其他空间。
- AI 只“提议”记录，真正写入由服务端校验权限和业务规则后执行；模型调用失败不能绕过权限。
- **提供方和模型由管理员配置**：用哪些提供方和模型、每类任务（聊天、文字记账、图片识别等）默认用哪个模型和降级顺序，由管理员通过管理命令或管理 API 调整，改了即时生效，不用重启。ChatGPT 订阅的登录需要浏览器回调到本机，只能在管理命令里完成；管理界面只显示登录状态和到期时间。
- **每次模型调用都计量**：记下用了多少 token（未缓存输入、缓存读取、缓存写入、输出），按该模型的官方 API 标价折算成本（走订阅也照此折算），计入发起它的空间和成员；成功和失败的调用都记。

详见 [AI 层设计](../engineering/ai-layer.md)。

## 10. 推进与验收路径

| 阶段 | 内容 | 回答的问题 |
|---|---|---|
| **A. 可行性** | 两个内部用户 ID、用户名密码登录、会话恢复、默认个人空间自动创建与空间隔离；默认模型提供方接入，图片与结构化输出小样；验证共享模型连接下不同空间的上下文不串用。 | 身份、隔离与模型能力能否按既定边界工作（不建公开注册和自动找回）。 |
| **B. 本地交互骨架** | Flutter 三界面、本机数据模型（按空间分区）、空间切换、应用锁、记录卡、编辑 / 撤销和离线 outbox（待发送队列）；用假数据把三条流程跑顺。 | 交互是否顺手。 |
| **C. 服务端与 AI 闭环** | Rust API、PostgreSQL、原图存储与模型适配层；补齐权限校验、同步幂等、原图留存和变更记录，再跑真实文字 / 图片流程。管理命令与管理 API（账号、模型配置、用量计量）、个人 API key。 | 端到端是否可靠。 |
| **D. 两台手机终验** | 在两台安卓测试机上验证安装、各自聊天（对方看不到自己的对话）、共同空间共享、各自默认个人空间互不可见、退出与重新加入、离线排队与恢复；两台设备在共同空间里看到的内容和同步结果必须一致。另用 API key 跑一遍：只读 key 能查不能写，读写 key 记的账在两台手机上都显示“通过 API key：名称”，撤销后立即不能用。再逐条走一遍下面的“规则 → 验收场景”对照表。 | 是否达到首版验收。 |

### 规则 → 验收场景对照

正常流程之外，下面每条已定的规则都要有对应的验收场景（“两台手机”既要测两个人各一台，也要测**同一个账号登录两台手机**）。

| 规则（决策） | 验收场景 |
|---|---|
| 追问可在任一台手机回答、不重复回答（P25–P27） | 同一账号两台手机同时打开同一张追问卡，几乎同时点不同的选项：只有一个回答生效，另一台显示“这个问题已在另一台手机上回答”，账只记一次。 |
| 修改冲突、撤销优先（P38、P56） | 同一账号两台手机：一台离线改金额，另一台撤销这笔；离线的那台联网后看到“这笔已被撤销”，只有点“恢复并改成我的版本”才会恢复；冲突解决前余额按服务器版本显示。 |
| 照片的移除与占用（P67、P68） | 一笔账带两张照片：编辑去掉其中一张，一天后这张从服务器清掉、变更记录显示“移除了一张照片”且不能点开；撤销这笔账后另一张照片照常保留，恢复后能看。两个空间各传同一张照片，两个空间的占用都包含它；这之后没有新上传或移除时，空间设置里的占用与管理侧当天的记录一致。 |
| 退出与重新加入（P13、P19、P52） | 有未上传内容时自己退出：先看到“有 N 条还没上传，退出后会丢弃”。手机离线期间被移出：联网后本机该空间内容被清除并看到提示。被移出又被加回：旧的排队内容不会提交进去，空间重新完整同步，旧记录重新关联到本人。 |
| API key 跟着成员身份走（P51） | 退出某空间后 key 立即访问不到它；重新加入后同一个 key 自动又能用；新加入的空间不用新建 key 就能用。key 不能新建空间、不能管理成员。 |
| 停止与重试（P27、P50） | 一句话说两笔，第一笔已记好、第二笔在追问时点停止：第一笔保留且能单独撤销，卡片写明“已记 1 笔，第 2 笔没有记”；再说一遍第二笔，第一笔不会重复。回复中途服务器出错后点“重试”，已记的账不重复。 |
| AI 不可用时手动记账（P34、P54） | 关掉 AI 接入后，新账号从零开始：在设置里手动建账户、设起始余额和拨入计划，用“手动记一笔”记账；排队中的内容选“改为手动填写”，AI 恢复后不会再记一遍。 |
| 币种与退款（P53） | 建空间时选币种（默认人民币），金额都按这个币种显示。对一笔支出做两次部分退款，累计超过原金额时被拒；原用途账户已归档时退款先问退到哪个用途（默认备用金）；撤销已归档账户上的旧账后，App 提示把余额转走。 |
| 每月拨入时间（P55） | 10 月 27 日设好每月 1 日拨入：10 月不补拨，11 月 1 日拨入一次；拨入日设 31 号时 11 月在 30 日拨；服务器停机跨过拨入日，恢复后只补拨一次；撤销一次拨入后余额正确。 |
| 转让与删除空间（P17、P18、P57） | 最后一位所有者退出时被引导先转让；转让给另一位成员后可以退出；只剩自己时删除空间要输入空间名，删除后不能恢复；默认个人空间没有删除和退出入口。 |
| 资料关联的更正（P44、P58） | 检查单关联错了家人，改成正确的家人后修改记录里看得到；已关联资料的家人只能归档、不能删除；再新建一个与已归档家人同名的家人，自动沿用原来那位，旧资料仍在他的时间线上。 |
| 模块权限的例外（P40） | （首版没有授权界面，用测试数据模拟）收回资料权限后，旧回复里的文字照常显示，资料卡显示“此内容你已无权查看”。 |
| 中英文（P48） | 两台手机分别用中文和英文界面：同一笔账的日期、数字按各自语言显示，币种符号相同；没改过名的预置分类按各自语言显示，改过名的两边一样；英文提问用英文回答。 |
| 升级失败与强制更新（P46、P47、P59） | 下载中断、安装包被篡改、拒绝“允许安装应用”授权时都有明确提示、能重试；进入强制更新时仍能查看数据，离线时拍的照片在更新后自动接着上传，不丢。 |
| 管理员重置密码（P49） | 管理员重置密码后，本人所有手机退出登录、原密码失效；本人下次登录时看到“你的密码在……被管理员重置”。 |

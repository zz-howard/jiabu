| G2 | **v1 就做流式**：文字逐步显示；组件块整块到达（先占位、后填满），不做组件字段级增量；稳定块 ID、按 ID 补丁、幂等事件、断线续传；最终消息服务端持久化并同步，重连 / 离线后以持久化版本为准 | 2026-10-26 | 不等整段生成完是基本体验；组件整块到达把复杂度控制在可验证范围；持久化版本优先保证多设备一致、离线可用 |
| G3 | 聊天交互做成**独立的开源库 ChatWeave，独立仓库**（[github.com/zz-howard/chatweave](https://github.com/zz-howard/chatweave)）：语言无关协议 + JSON Schema、Rust crate、Flutter 两层包（纯 Dart 核心 + 界面），不含任何家簿概念；家簿开发期用本地路径依赖，库发布后改版本依赖 | 2026-10-26 | 强制边界，避免记账概念混进通用聊天层；可复用；库用非记账的示例 App 跑测试与 golden |
| G4 | **v1 确定性映射，无 UI Agent**：服务端把 AI 结果按规则映射成语义块，客户端按块类型查注册表选组件；View 协议只保留到 Phase 2 | 2026-10-26 | 普通展示不额外调用模型：低延迟、低成本、可测试 |
| G5 | **v1 最小动作集**：选项选择、确认 / 取消、表单提交（用于追问与首次设置）；服务端 Action Registry 做参数校验，再经统一的 `authorize(member, module, action)`；UI 动作不等于工具授权；不可撤销的操作必须经确认块；日常记账仍直接入账、靠撤销保证安全（P2 不变） | 2026-10-26 | 覆盖最常见的交互；客户端和模型都无法凭空获得执行权限 |
| G6 | **家簿只用 ChatWeave 的一对一场景**（库本身也支持群聊）；交互卡仍按库的规则“点了先显示提交中、服务端确认后才显示结果”，理由是服务端可能拒绝（权限、相关记录已变化或删除、校验不通过）且同一用户可能在两台手机上操作，而不是多人抢答 | 2026-10-26 | 对应 P23；保持与库的通用规则一致，不为家簿另做乐观显示 |
| G8 | **中断与层级步骤用 ChatWeave 的通用机制**：追问和确认让回复暂停（`message.paused`），回答走动作通道（点选项、打字回答 `freeText`、确认 / 取消），返回 `resume`，同一条回复继续（`message.resumed`，事件序号接着数）；暂停中的回复以服务端保存的暂停版本为准，事件日志过期、服务端重启、换设备都能继续；停止 / 改发别的话 / 过期都结束这条回复。家簿 v1 不用子 Agent，但 ChatWeave 的层级步骤（委派步骤 + `parentStepId`，最多 3 层，默认收起）留给以后。取代 G7 中“需要确认的一步结束这一轮、回答后由新回复继续”的部分 | 2026-10-26 | 对应 P25 与 A9；通用部分进库，家簿只提供动作处理器、步骤说明和外观 |
| G7 | **过程条用 ChatWeave v1 的运行步骤**：步骤事件对齐 AG-UI 1.0 的 `STEP_STARTED` / `STEP_FINISHED`，与回复同一条流、带序号、可续传；回复结束时随消息保存精简的步骤记录（说明、最终状态、耗时、可选结果说明），与内容块分开，不进纯文本兜底；客户端声明 `stream.steps`；“仍在处理”这类没有具体步骤的等待仍用临时提示，有步骤时以步骤为准；外观为手账风格的 `JiabuProcessStrip`（设计规范 4.17） | 2026-10-26 | 对应 P24 与 A8；通用部分进库，家簿只提供步骤说明和外观 |
| G9 | **中断卡固定带“输入其他内容”、输入框锁定与“回答”标签进 ChatWeave 库**：库默认给每张中断卡加“输入其他内容”（宿主可按中断关闭，家簿保持开启），三种交互卡都可以用 `freeText` 回答；暂停时输入框锁定、点“输入其他内容”进入回答状态，作为库级的输入框契约；有中断开着时新消息到达服务端，家簿（离线排队的消息）先按停止关闭暂停中的回复再开始新的一轮。取代 G8 中“打字回答只限允许文字回答的选项卡”和“改发别的话结束这条回复”的部分 | 2026-10-26 | 对应 P26 与 C13；通用部分进库，家簿只提供外观和动作处理器 |
| G10 | **ChatWeave 的版本**：家簿 v1 期间按固定提交依赖，每次升级一个单独 PR；协议 0.1 一致性夹具在 Rust 与 Dart 两边全过、且家簿验收阶段 D 通过后发布 0.1.0（crates.io / pub.dev），家簿改为版本依赖；许可证 MIT（已添加）。家簿用库的 `…/messages/{id}/stop` 命名，不用 `startRejected`（消息都经 outbox，统一先停止再开始）。关闭待定问题 18（[技术方案 10.9](../engineering/technical-design.md#109-chatweave-的版本待定问题-18)） | 2026-10-27 | 接口还会随家簿变，先用固定提交；真实宿主验收后再承诺版本 |
